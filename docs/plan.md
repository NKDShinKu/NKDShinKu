# NKDShinKu 个人站规划清单

## 项目目的

这个项目不是单纯做一个好看的个人主页，而是一个长期学习型项目。

它要承载四件事：

- 收集个人笔记和博客文章
- 整理个人项目和作品集
- 保存学习 Demo 和实验记录
- 逐步学习动画、部署、服务端、网络和运维知识

核心原则：**先做出一个能访问、能更新的最小版本，再逐步升级。**

---

## 推进原则

- 每次只完成一个小目标
- 页面先能用，再做精致
- 内容先用本地文件或简单数据管理
- 动画先少量加入，后面逐步深入
- 第一阶段不做后端、不做数据库、不做登录后台
- 每个阶段结束时都要能运行、能构建、最好能部署

---

## 阶段总览

| 阶段 | 目标 | 结果 |
|------|------|------|
| Phase 0 | 明确方向 | 知道网站要放什么内容 |
| Phase 1 | 做出第一版 | 网站能浏览、能展示基础内容 |
| Phase 2 | 补充内容 | 项目、笔记、Demo 有真实沉淀 |
| Phase 3 | 学习动画 | 网站开始有交互和视觉特色 |
| Phase 4 | 上线部署 | 网站可以公开访问并持续更新 |
| Phase 5 | 学习后端 | 从静态数据升级到 API 和数据库 |
| Phase 6 | 学习运维 | 理解服务器、Nginx、Docker、HTTPS |

---

## Phase 0：明确方向

### 目标

先确定这个网站第一版到底要展示什么，避免一开始陷入复杂架构。

### 要做的事

- [ ] 确定网站名称
- [ ] 写一句话介绍这个网站
- [ ] 写一段个人介绍
- [ ] 准备 3 个项目条目
- [ ] 准备 3 篇笔记草稿
- [ ] 准备 2 个 Demo 想法

### 内容建议

项目条目可以写：

- 项目名称
- 一句话介绍
- 使用技术
- 项目链接
- 当前状态

笔记草稿可以从这些主题开始：

- 为什么做这个个人站
- Vue 项目搭建记录
- npm update 和依赖版本理解
- React、Vue、Next.js 的区别
- 部署到 Vercel 的流程记录

Demo 想法可以从这些开始：

- GSAP 入场动画
- 滚动触发动画
- 页面切换动画

### 完成标准

- 你能说清楚这个站点是做什么的
- 第一批内容已经准备好
- 明确第一版只做前端展示

---

## Phase 1：做出第一版网站

### 目标

用当前 Vue 项目做出一个最小可用版本，让别人打开网站后能知道你是谁、你在学什么、你做过什么。

### 要做的事

- [ ] 清理默认脚手架页面
- [ ] 做出首页
- [ ] 做出项目展示
- [ ] 做出笔记展示
- [ ] 做出 Demo 展示
- [ ] 做出基础导航
- [ ] 适配手机端浏览
- [ ] 确认本地开发正常
- [ ] 确认生产构建正常

### 首页第一版只需要回答

- 我是谁
- 我现在关注什么方向
- 这个站点里有什么内容
- 用户可以从哪里进入项目、笔记和 Demo

### 完成标准

- 首页能正常展示
- 项目、笔记、Demo 三类内容都能看到
- 页面在手机和电脑上都能正常浏览
- 本地运行和构建都没有问题

---

## Phase 2：补充真实内容

### 目标

让网站从空壳变成真正的个人知识库和作品集。

### 要做的事

- [ ] 补到至少 5 个项目条目
- [ ] 补到至少 5 篇笔记
- [ ] 补到至少 3 个 Demo
- [ ] 给内容加标签
- [ ] 给内容加时间
- [ ] 给每个项目补充“学到了什么”
- [ ] 给每个 Demo 补充“练习目标”

### 推荐内容方向

项目可以记录：

- 做这个项目的原因
- 主要功能
- 用到的技术
- 遇到的问题
- 后续改进方向

笔记可以记录：

- 前端框架理解
- Vue 组合式 API
- TailwindCSS 使用经验
- GSAP 动画学习
- Vite 构建理解
- 部署和域名配置

Demo 可以记录：

- 动画实验
- 组件实验
- 小工具实验
- 网络请求实验
- Canvas 或 3D 实验

### 完成标准

- 网站内容不再是占位文字
- 每个栏目都有真实内容
- 后续新增内容时知道应该放在哪里

---

## Phase 3：系统学习动画

### 目标

把动画作为这个项目的学习特色，但不让动画影响阅读和使用。

### 学习顺序

1. CSS 过渡和 hover 效果
2. GSAP 基础动画
3. GSAP Timeline
4. GSAP ScrollTrigger
5. 页面切换动画
6. Canvas 动画
7. Three.js 或 Spline 3D 效果

### 要做的事

- [ ] 给首页增加一个简洁的入场动画
- [ ] 给项目卡片增加 hover 反馈
- [ ] 做一个滚动触发动画 Demo
- [ ] 做一个页面切换动画 Demo
- [ ] 做一个 Canvas 或 3D Demo
- [ ] 每个动画 Demo 配一篇学习笔记

### 控制原则

- 首页可以稍微有表现力
- 博客正文保持克制，优先阅读
- 动画不能造成明显卡顿
- 移动端也要检查动画体验
- 不要为了炫技牺牲内容清晰度

### 完成标准

- 网站有明确的视觉记忆点
- 至少有 3 个动画 Demo
- 你能解释每个动画用了什么技术、解决了什么问题

---

## Phase 4：上线部署

### 目标

把网站发布到公网，让它成为可以分享、可以持续更新的个人站。

### 要做的事

- [ ] 选择部署平台，优先 Vercel
- [ ] 连接 GitHub 仓库
- [ ] 配置自动构建
- [ ] 部署第一版网站
- [ ] 检查线上页面是否正常
- [ ] 检查刷新页面是否正常
- [ ] 检查移动端线上效果
- [ ] 后续绑定自定义域名
- [ ] 了解 HTTPS 是如何生效的

### 你会学到

- 静态站点部署
- GitHub 和部署平台联动
- 自动构建和自动发布
- 域名解析基础
- HTTPS 基础概念

### 完成标准

- 有一个可以公开访问的网址
- 提交代码后可以自动更新线上站点
- 网站可以放到简历、GitHub 主页或社交资料里

---

## Phase 5：加入后端能力

### 目标

当静态站点稳定后，再加入服务端，学习 API、数据库和后台管理。

### 推荐顺序

1. 学习 Node.js 服务端基础
2. 做一个简单 API 服务
3. 接入数据库
4. 实现项目、笔记、Demo 的读取接口
5. 实现新增、编辑、删除
6. 加入简单登录
7. 做一个只给自己使用的管理入口
8. 前端从本地数据切换为接口数据

### 暂时不要一开始就做

- 复杂权限系统
- 多用户系统
- 评论系统
- 微服务
- 复杂后台模板

### 你会学到

- 服务端路由
- 请求和响应
- RESTful API
- 数据库设计
- 登录认证
- 前后端接口协作

### 完成标准

- 后端服务可以独立运行
- 前端能从 API 获取内容
- 数据能保存到数据库
- 可以通过简单后台维护内容

---

## Phase 6：学习运维

### 目标

从“会用平台部署”升级到“理解部署背后的服务器和网络知识”。

### 推荐顺序

1. 学习 SSH 登录服务器
2. 学习 Linux 基础命令
3. 学习端口、防火墙、安全组
4. 在服务器上部署前端静态文件
5. 使用 Nginx 托管网站
6. 使用 Nginx 反向代理后端 API
7. 配置域名解析
8. 配置 HTTPS 证书
9. 学习 Docker 部署
10. 配置自动部署
11. 学习日志查看和简单监控

### 你会学到

- Linux 基础
- 服务器目录和权限
- 端口和防火墙
- Nginx 静态服务
- Nginx 反向代理
- DNS 解析
- HTTPS 证书
- Docker 基础
- CI/CD 自动部署
- 日志排查

### 完成标准

- 网站可以部署在自己的服务器上
- 域名和 HTTPS 正常
- 后端服务能稳定运行
- 出问题时知道去哪里看日志

## 近期最小行动清单

当前最重要的是先完成第一版，不要发散。

按这个顺序做：

1. 写好网站名称和一句话介绍
2. 写好个人介绍
3. 准备 3 个项目条目
4. 准备 3 篇笔记草稿
5. 准备 2 个 Demo 想法
6. 清理默认首页
7. 做出首页、项目、笔记、Demo 的基础展示
8. 本地构建通过
9. 部署到 Vercel

完成这 9 件事后，再开始补动画、优化视觉、学习后端和运维。

---

## 现在先不要做的事

这些内容以后可以做，但不适合第一阶段：

- 后端服务
- 数据库
- 登录系统
- 后台管理
- Docker
- 云服务器长期运维
- 复杂搜索
- 评论系统
- 复杂权限
- 过度设计目录结构
- 一开始就追求完整博客系统

原因：它们都会提高复杂度，但不会帮助第一版更快上线。

---

## 判断是否偏离目标

当你不确定某个功能现在该不该做时，问自己：

- 它能帮助我展示项目吗？
- 它能帮助我沉淀笔记吗？
- 它能帮助我练习动画或前端工程吗？
- 它能帮助我学习部署、服务端、网络或运维吗？
- 它现在必须做吗，还是以后再做也可以？

如果它不能帮助当前阶段目标，就先放到后面。

---

## 最终目标

这个项目最终应该变成你的长期学习基地：

- 学到的新知识，沉淀成笔记
- 做过的小项目，整理成作品
- 试过的新技术，保存成 Demo
- 遇到的部署和网络问题，记录成排错经验
- 随着项目成长，逐步建立前端、服务端、网络和运维的完整知识链路
