# 博客方案评估

> 对 `docs/博客项目背景.md` 中方案的逐项合理性分析、风险与前置条件。
> 评估时间：2026-08（M0 框架搭建阶段）。技术版本以本仓库 `package.json` 为准。

## 总体结论

**方案可行，零成本路线成熟**。参考仓库（minorcell/minorcell）即为同路线，所有组件均能
免费覆盖个人博客场景。整个方案中没有任何"不可行"项，但有若干**前置条件**与**国内网络
相关风险**，已在下方逐项列出并写进部署清单。

本次会话已确认的决策：

| 决策点       | 结论                                                  |
| ------------ | ----------------------------------------------------- |
| 仓库可见性   | public（已确认）→ GitHub Pages 免费版 + giscus 均可用 |
| git 历史     | 保留历史，已提交对旧 Vue 尝试的清理                   |
| 初始范围     | 只搭项目框架 + 首页占位，其余模块按路线图推进         |
| giscus       | 暂缓引入（路线图 M3/M4），前置条件已写进清单          |
| Bangumi 数据 | 浏览器端实时请求（数据新鲜、无构建依赖）              |
| 旧 skills    | 不恢复，按需重装                                      |

## 逐项评估

### 1. 框架：Next.js SSG ✅ 合理

- `output: "export"` 全静态导出与 GitHub Pages 是天然组合；Next 16.3 已稳定。
- **代价（已写进 AGENTS.md 红线）**：静态导出下 API Routes、middleware、ISR、
  Server Actions、动态渲染全部不可用；`next/image` 必须 unoptimized。
  这个限制对博客场景影响很小，但要求"动态数据一律浏览器端获取"的开发纪律。
- 版本搭配注意：TypeScript 锁 5.9（TS 7 生态兼容未验证）、ESLint 用 9.x flat config。
- 备选对比：Astro 对内容站更轻量，但方案已定 Next.js 且参考仓库同栈，维持原案。

### 2. 部署：GitHub Actions + GitHub Pages + 自定义域名 ✅ 合理

- 仓库 public → 免费 Pages 可用；项目仓库（非 `<user>.github.io`）绑定自定义域名后
  站点在域名根目录提供服务，**无需 basePath**。
- CI 流水线已就绪（`.github/workflows/deploy.yml`）：lint → typecheck → 静态导出 →
  Pagefind 索引 → 上传 artifact → deploy-pages。
- 前置条件（见部署清单）：仓库 Settings 中把 Pages 源切到 **GitHub Actions**；
  域名 `nkdshinku.com` 在 Cloudflare 添加 DNS 记录（A 记录或 CNAME 二选一）；
  `trailingSlash: true` + `.nojekyll` 已配置，保证无扩展名 URL 可访问。
- 备选对比：域名在 Cloudflare 时，**Cloudflare Pages** 是同生态替代（私仓也免费、
  控制台统一、预览部署），当前不采用但保留为退路（若 GH Pages 国内访问质量差可迁移，
  项目本身零改动）。

### 3. 图片存储：Cloudflare R2 ✅ 合理

- 免费 10GB 存储 + 无出口流量费，个人博客配图绰绰有余。
- 注意点：
  - `r2.dev` 公开域名仅适合测试（有速率限制与使用条款限制），**正式使用需绑定
    自定义域**（建议 `static.nkdshinku.com`，同时获得 Cloudflare CDN 缓存）。
  - SSG 下图片直接引用 R2 公网 URL（unoptimized），需显式宽高防 CLS。
  - 上传走 S3 兼容 API（rclone / aws cli），清单给出配置步骤。
- 版权提醒：二次元插图请使用自绘 / AI 生成 / 明确授权的素材，避免直接搬运他人作品。

### 4. 搜索：Pagefind ✅ 合理

- 纯静态索引、无服务端、零成本，与 SSG 路线完全匹配；已在 CI 中作为构建后步骤接入。
- 中文支持可用（社区有 Astro + Pagefind 中文实践，见
  [Astro博客添加Pagefind搜索](https://eastondev.com/blog/zh/posts/dev/20251203-astro-pagefind-search-guide/)），
  后续可用 `--language zh` 参数微调。
- 前端 UI 后续接入（`@pagefind/default-ui` 或自定义组件），属路线图 M3。

### 5. 评论：giscus ⏸ 合理但暂缓

- 前置条件（仓库已 public ✓）：开启 Discussions → 安装 giscus App 并授权仓库 →
  在 giscus.app 生成 repoId / categoryId 配置。清单已列出全部步骤。
- 风险：评论者需 GitHub 账号登录；GitHub API 在国内的可用性**上线前需实测**。
  若体验差，备选 Waline / Twikoo（均需服务端或免费托管，与零成本目标有轻微冲突）。
- 本次按用户决策暂缓引入。

  - CI/部署排错经验不依赖 skill，已沉淀为 AGENTS.md 第 9 节与部署清单。

## 风险与待验证项

1. **Bangumi API 浏览器端跨域（CORS）**：`api.bgm.tv` 的浏览器直连能力需在 M3 实测；
   若跨域受限，备选：构建时抓取、公共 CORS 代理或 Cloudflare Worker（免费额度内）。
2. **GitHub Pages 首次自定义域名**：DNS 先生效，HTTPS 证书签发需数分钟至数小时；
   期间 HTTP 可访问。Cloudflare 下建议开启 DNS Proxy 时注意与 Pages 的 TLS 兼容性
   （默认"仅 DNS"最稳）。
3. **国内访问质量**：GitHub Pages 在国内速度一般；如不可接受，迁移 Cloudflare Pages
   （代码零改动）或 Cloudflare 代理（需备案外的合规考量，自行评估）。
4. **R2 公开访问**：r2.dev 域名有条款限制，正式环境务必自定义域。
5. **图片素材版权**：见上文 R2 节提醒。
