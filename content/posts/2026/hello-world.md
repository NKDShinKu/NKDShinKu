平时学的东西不少，但大多停留在「收藏夹吃灰」的阶段——笔记散落在各种软件里，时间一长连自己都找不到。做过的小项目躺在硬盘和 GitHub 仓库里，除了简历上的一行字，没有任何地方能让人点开看一眼。追番的记录散在 Bangumi，踩过的坑留在聊天记录里。

所以想要一个**完全属于自己的地方**：把学习、踩坑、造玩具的过程沉淀下来，把项目摆出来，把兴趣装进去。域名是我的，数据是我的，长什么样也是我说了算——不用担心平台改规则、算法限流量，或者哪天服务关停，一段记忆跟着蒸发。

这就是这个博客的由来。

## 从一版废弃的 Vue 尝试说起

第一版其实是用 Vue 手搓的。搭到一半意识到一个问题：我想要的不是一个「能显示文章的页面」，而是一条完整的内容管线——Markdown 渲染、代码高亮、标题锚点、标签归档、搜索、RSS、评论、部署自动化。这些东西每一件都要自己造轮子，轮子造完，底座铺完，热情也耗得差不多了。

于是推倒重来，换成 **Next.js（App Router）+ 全静态导出**。这次想清楚了核心决策，只有一个：**整站就是一堆静态文件**。没有 API 路由、没有数据库、没有运行时，`git push` 之后 CI 自动构建、生成搜索索引、部署上线，全程没有任何服务器参与。

这个决策带来的是一连串的轻松：托管零成本（GitHub Pages 对公开仓库免费）、安全性天然拉满（没有服务器就没有可被打挂的东西）、迁移自由（静态文件扔给任何一家托管都行，国内访问不理想还可以整体迁去 Cloudflare Pages，代码零改动）。

代价也存在：一切「动态」的能力都要找静态友好的方案，选型时多绕了些弯路。但事后看，这些弯路正是这个项目最有意思的部分。

## 技术选型：每一步都有理由

把动态能力外包出去的架构，落到具体选型上是这样的：

- **评论 → [giscus](/posts/static-blog-giscus-guide/)**。数据存在仓库自己的 GitHub Discussions 里，零服务器，评论者用 GitHub 账号发言。放弃了需要自建后端的 Waline 和 Twikoo——不是它们不好，是「为了评论引入一个服务端」违背了全静态的初衷。
- **图片 → Cloudflare R2**。自定义域直连，出口流量免费，免费额度对个人博客近乎无限。文章封面和插图全部走图床，仓库里不放二进制大图。
- **追番数据 → Bangumi 公开 API**。浏览器端直连，实测 CORS 放行、并发无限流，不需要任何代理层。我看什么，ACG 橱窗就自动长什么。
- **搜索 → Pagefind**。构建期对产物生成纯静态索引，搜索体验接近全文检索，依然零服务端。

框架之外的选型，一句话一个理由：

- **TypeScript（strict 模式）**：类型即文档，构建期快速失败优于线上静默出错；
- **TailwindCSS 4**：设计 token 全部 CSS-first 管理，配色、字号、圆角改一处全站生效；
- **组件全自研**：个人博客的交互面很小，引入组件库是负资产；仅在最需要无障碍保证的弹窗处引入了 Radix 无样式原语；
- **GSAP 做动效**：滚动入场、极光漂移，全部尊重系统的「减弱动态效果」偏好；
- **Iconify + MDI 图标集**：按需生成 CSS，不背一整套图标库；
- **unified（remark/rehype）内容管线**：Markdown 渲染的每一步（锚点、高亮、图表占位）都可插拔；
- **Shiki 双主题代码高亮**：亮暗两套配色在构建期烘焙进 HTML，切换主题零闪烁。

语言只有中文，包管理用 pnpm，类型锁在 TypeScript 5.9——这些没什么好展开的，纯粹是「选了就不折腾」的部分。

## 设计：天空与夜空

视觉方向在动工前就定了性：**浅色为主、蓝白基调、柔和阴影、圆润造型**，轻微的 ACG 气质与轻科技氛围——我给设计师（AI）的关键词只有两个：**天空、夜空**。

最终落地的方案叫 Soft ACG Fusion：玻璃态卡片 × 极光渐变背景 × 萤火粒子，主色是天蓝 × 樱粉 × 暮紫。原则是「二次元素材克制使用」——氛围藏在背景里，排版、配色和交互才是主角。白天是晴空，夜晚是星夜，两套主题共用同一套设计 token。

还有一条贯穿全站的坚持：可访问性不是可选项。对比度达标、键盘可达、焦点可见、动效尊重系统偏好、图片必有替代文本——这些在走查里是硬性关卡，不是锦上添花。

## AI coding：与 AI 结对完成的项目

这个站点还有一个不太寻常的地方：**它是我和 AI 结对完成的**——从第一行代码到上线部署，AI 全程跟进。

分工大致是这样的：我提需求、定方向、做每一个决策，并且为审美和质量把关；方案调研、代码实现、细节走查、文档整理由 AI 跟进执行。听起来像标准的「产品经理 + 工程师」配置，但双方是同一个身体里的两个大脑。

这个过程里最大的收获不是「写得快」，而是**决策记录的价值**。从「要不要做用户系统」到「品牌色底要不要受对比度限制」，十九个正式决策全部落了档：每个决策是什么、备选是什么、为什么这么选。写下这些的过程逼着每个模糊的想法变清晰，也让任何一次回溯都有据可查——这篇 文章里聊到的每一个选型，背后都有对应的决策编号。

另一个观察：AI 时代做个人项目，**瓶颈从「写代码的能力」变成了「把需求说清楚的能力」**。AI 能在几分钟内实现一个组件，但「这个组件该不该存在、长什么样、交互是否优雅」，依然需要对方向负责的人一关一关地审。工具越强，判断力越值钱。

## 一些明确不做的事

选型之外，还有一份「反向路线图」——明确不做的事，写下来防止自己手痒：

不做用户系统和登录，不做多语言，不做友链页面，不做访问统计（隐私优先），不做实时聊天和弹幕，不做付费打赏。这个站的复杂度预算只留给内容和体验本身。

## 接下来打算做什么

**博客本身会持续迭代**：动效细节、性能、移动端体验，都按「上线只是及格线」的标准慢慢磨。

**文章会持续沉淀**：建站实战系列（评论系统、图床工作流、性能优化这些刚亲手做过的事）、前端学习的笔记与教程，往这两个方向长。

**实验室会持续加玩具**：学到新技术，先做成能跑的小东西放进来。

**ACG 橱窗跟着我自己长**：追番数据连着 Bangumi 账号，看什么长什么。
